Desenvolva uma aplicação web local completa e funcional para criação visual de layouts de sites e sistemas; este projeto NÃO é uma landing page, mockup ou demonstração visual, mas uma ferramenta de edição semelhante conceitualmente a Canva/Figma/FlutterFlow, porém com identidade própria e sem copiar seus elementos visuais; público principal: estudantes, especialmente Ensino Médio, em contexto educacional da Etec Sales Gomes, portanto priorize interface limpa, intuitiva, moderna, calma, criativa e fácil de entender por usuários sem conhecimento avançado de programação; a aplicação deve funcionar localmente, sem login, cadastro, autenticação, perfil, senha ou dependência obrigatória de servidor/conta externa; tecnologias principais: HTML, CSS e JavaScript, com React permitido e recomendado para estruturar o editor, componentes e gerenciamento de estado quando trouxer vantagem, Node.js apenas como suporte de desenvolvimento/build se necessário, não utilizar Flask, MySQL ou banco externo sem necessidade real; arquitetura modular, organizada e reutilizável, evitando arquivo monolítico, separando componentes, estilos, estado do projeto, páginas, elementos, editor, persistência e geração de código; fluxo principal obrigatório: MENU → escolha de template → EDITOR VISUAL → adicionar/mover/redimensionar/editar componentes → criar múltiplas páginas → salvar → gerar código a qualquer momento → visualizar/copiar/exportar resultado; aplicação composta por três áreas principais: Menu, Criação do Layout e Gerador de Código, sendo que “Gerar Código” também deve estar disponível diretamente dentro do editor a qualquer momento e não somente na terceira área; Menu deve possuir navbar com Menu, Criação do Layout e Gerador de Código e apresentar templates em cards organizados em grade; templates obrigatórios: Layout em Z, Layout em F, Diagrama de Gutenberg, Coluna Única, Duas Colunas/Split-Screen, Grid/Card-Based, Assíncrono/Ziguezague, Tela Cheia/Hero Background, Mondrian, Silhueta e Circo; cada template deve ser uma estrutura inicial funcional do projeto, nunca uma imagem estática, e ao selecioná-lo o editor deve abrir já preenchido com uma composição correspondente ao modelo escolhido; hover do template deve mostrar nome, descrição curta e explicação de sua finalidade; editor visual deve possuir barra superior, painel lateral, área central de canvas e controles de páginas/zoom, inspirado na organização de editores visuais profissionais, usando a imagem fornecida como referência de estrutura/experiência, mas sem copiar identidade visual, layout exato ou elementos proprietários; canvas é o núcleo do sistema e deve representar a página real em edição, permitindo seleção visual, movimentação, drag & drop, redimensionamento, edição, exclusão, reorganização e alteração de propriedades; drag & drop é obrigatório e deve modificar o estado real do projeto, permitindo arrastar componentes do painel para o canvas e posicioná-los no local correspondente; componentes iniciais obrigatórios: Caixa de Imagem, Caixa de Título, Bloco de Parágrafo, Botão/CTA, Link de Navegação, Campo de Texto, Card e Rodapé; componentes devem ser objetos reais do editor, não elementos decorativos, e possuir propriedades configuráveis conforme o tipo, incluindo conteúdo, texto, posição, largura, altura, tamanho, alinhamento, margem, espaçamento, cor, fundo, borda, raio, fonte, imagem, link, destino, visibilidade, ordem/camada e outras propriedades essenciais; Card deve, quando viável, funcionar como container capaz de receber componentes internos; quando um elemento estiver selecionado deve existir indicação visual clara e controles para mover, redimensionar, editar e excluir; o projeto deve possuir suporte a múltiplas páginas/telas, permitindo criar, selecionar, renomear, excluir e navegar entre páginas, com possibilidade de relacionar botões/links a páginas específicas; navegação deve ser preservada na exportação, por exemplo botão “Continuar” → Página 2; permitir criação de layouts responsivos e considerar Flexbox, CSS Grid, media queries e unidades relativas, sendo responsabilidade principal do gerador produzir HTML/CSS responsivo; salvamento deve ocorrer localmente, sem conta online, utilizando mecanismo adequado do navegador ou outra solução local, permitindo continuar o projeto posteriormente; é desejável também permitir exportar/importar o projeto editável em JSON; cada projeto deve possuir uma representação estruturada de dados semelhante a Projeto → páginas → elementos → propriedades, e cada elemento deve possuir dados suficientes para reconstrução e geração de código, como id, tipo, posição, tamanho, conteúdo, estilos, propriedades, página, ordem/camada, link e filhos quando aplicável; NÃO gerar código a partir de screenshot ou imagem do canvas, mas a partir do estado estruturado do projeto; o gerador deve interpretar os objetos do editor e convertê-los em HTML/CSS/JavaScript reais; o usuário deve poder gerar código em qualquer estágio da criação e o resultado deve refletir exatamente o estado atual naquele momento; após novas alterações, gerar novamente deve produzir código atualizado; saída obrigatória: pelo menos um arquivo .html funcional e um arquivo .txt ou .md contendo o código bruto; o HTML deve representar de forma real o layout criado, incluindo estilos e comportamentos, e preferencialmente ser autocontido ou possuir referências locais corretas, permitindo abrir diretamente no navegador; código exportado deve ser simples, legível e estudável, priorizando HTML/CSS/JavaScript mesmo que React seja utilizado internamente no editor; páginas, links, botões, estilos, estrutura e componentes criados no canvas devem possuir correspondência no código exportado; o sistema não deve criar botões falsos, menus meramente decorativos ou um canvas que apenas pareça funcional; não implementar login, cadastro, autenticação, dependências desnecessárias de internet, templates estáticos, exportação apenas visual ou clone literal de Canva/Figma/FlutterFlow; identidade visual própria deve utilizar princípios de Design Digital, teoria das cores e psicologia das cores, mantendo equilíbrio, clareza, criatividade e conforto visual, sem excesso de elementos chamativos; organização recomendada do editor: barra superior para ações como salvar/gerar código, painel lateral para componentes, canvas no centro, área inferior/lateral para páginas e controles de zoom; caso alguma funcionalidade avançada seja tecnicamente difícil, implemente primeiro uma versão funcional e coerente em vez de criar apenas aparência; prioridades de implementação: 1) estrutura e navegação, 2) Menu/templates, 3) editor, 4) canvas, 5) drag & drop, 6) componentes editáveis, 7) múltiplas páginas, 8) salvamento local, 9) gerador de código, 10) exportação HTML funcional/responsiva, 11) refinamento UI/UX, 12) recursos secundários; o resultado final deve permitir ao usuário escolher um template, abrir um projeto, editar visualmente, adicionar componentes, arrastá-los, redimensioná-los, alterar propriedades, criar páginas, conectar navegação, salvar localmente e gerar/exportar código funcional sem reiniciar o projeto; antes de implementar, analise toda a especificação, defina uma arquitetura coerente, descreva brevemente a estrutura técnica e somente então desenvolva a aplicação; entregue estrutura de pastas, arquivos completos, dependências, instruções para execução local e explicação objetiva de editor, estado, templates, salvamento e gerador de código; regra central de interpretação: ESTA APLICAÇÃO É UM CONSTRUTOR VISUAL DE LAYOUTS, NÃO UM SITE SOBRE LAYOUTS; templates são pontos de partida, componentes são objetos manipuláveis, canvas é o núcleo, drag & drop é interação real, múltiplas páginas representam o projeto, salvamento preserva o estado e o gerador converte o estado atual em HTML/CSS/JavaScript funcional.
